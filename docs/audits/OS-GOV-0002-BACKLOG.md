## Ordem recomendada

1. `OS-IMP-0009` para recuperar evidência executável.
2. `OS-IMP-0002` para integrar o pipeline do Module System.
3. `OS-IMP-0003`/`OS-IMP-0004` para fechar lifecycle e caminho oficial.
4. `OS-IMP-0007` para validar o Admin sobre o snapshot real.
5. `OS-IMP-0006` e `OS-GOV-0003` para reconciliação documental formal.
6. `OS-PLAN-0001` somente quando houver decisão de produto/arquitetura para Finance.

## Próxima task de implementação recomendada

A próxima task deve ser `OS-IMP-0002`, após revisão/aceite desta auditoria. O motivo técnico é que o Kernel, Runtime e Admin já possuem superfícies de observabilidade para módulos, mas o caminho padrão termina em discovery vazio e não conecta as implementações especializadas. Corrigir essa integração produz a evidência mínima necessária para validar Runtime Bootstrap, `/modules`, `modulesLoaded` e os próximos estados de lifecycle sem ampliar Finance, Builder ou Hosting.
